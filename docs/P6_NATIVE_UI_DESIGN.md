## 1. 目标与边界

把现有“换成 WinUI 控件、布局仍沿用 Avalonia”的界面，重设计为具有 Windows 11 原生应用层级与交互习惯的产品。参考 Windows 11 设置的侧边导航、页面标题、分类、说明、设置卡片和渐进展开方式。

本阶段覆盖主窗、插件浏览与详情、设置、P4/P5 工具窗和通用对话框。只换配色、圆角、字体或背景材质不满足目标；必须改善信息架构、入口组织和操作层级。插件管理仍需要高效的多选列表与数据视图，不把每个插件都改成占据大量空间的设置卡片。

允许调整页面、工具入口、分组和窗口布局；保留 Core 业务行为、文件格式、设置含义、命令语义和既有功能。Alt 作为业务核对基线保持只读，旧界面布局不再作为必须复刻的标准。不在本阶段进行无关业务重构、功能扩展或发布打包。

## 2. 当前界面的改版依据

以下为源码阅读发现，不代表实际运行测评：

| 区域 | 当前结构 | P6 要解决的问题 |
|---|---|---|
| 主窗口 | 顶部 MenuBar、浏览区、底部检查/推送按钮 | 页面导航与业务命令混在传统菜单中，缺少清晰页面层级 |
| 设置窗口 | 单个长 ScrollViewer、标题与多层 Border、密集表单 | 缺少分类导航、设置说明与稳定的设置行布局 |
| 公共样式 | 从 Alt 对应转换的标题/属性样式，Level1BorderStyle 使用灰色 2px 边框 | 容器、间距与主题资源未形成一致规范 |
| 插件浏览与详情 | 双 ListView、分栏、嵌套属性与展开区 | 保留虚拟化和操作效率，重新梳理工具栏、筛选、详情及状态层级 |
| 工具窗 | 逐个迁移的独立表单与列表 | 统一标题、命令区、列表、空态、进度、异常和关闭行为 |

源码定位：[MainWindow.xaml](../FireAxe.WinUI3/Views/MainWindow.xaml)、[AppSettingsWindow.xaml](../FireAxe.WinUI3/Views/AppSettingsWindow.xaml)、[Styles.xaml](../FireAxe.WinUI3/Views/Theme/Styles.xaml)、[AddonNodeExplorerView.xaml](../FireAxe.WinUI3/Views/AddonNodeExplorerView.xaml)、[AddonNodeView.xaml](../FireAxe.WinUI3/Views/AddonNodeView.xaml)。

## 3. 信息架构与导航

主窗采用原生侧边导航组织“插件库”“工具”“下载”等主要任务，设置与关于放在稳定的辅助入口。具体分类在实施时按现有命令清单确定，确保每个旧入口都有明确去向。优先使用 NavigationView，窄窗自动切换为紧凑或折叠导航。

内容区统一为“页面标题与说明 → 页面主命令 → 工作内容 → 状态反馈”。打开目录、导入、检查、推送、启动游戏应按任务与作用范围分布；高频命令直接可见，低频命令进入溢出菜单，破坏性命令有清楚文案与既有确认流程。

页面切换保留当前目录、筛选、选择和滚动等必要上下文；返回操作区分应用页面返回与插件组内返回。禁止因切换导航重复构造 VM、重复订阅或重复启动扫描/下载。

工具入口改为分组的功能卡片或列表，提供名称、简短说明与可用状态。根据用户 2026-11-11 实测反馈，设置、关于、下载及工具必须在同一个主窗口内显示，次级页面不得另开应用窗口。同步调整页面宿主、返回、窗口服务与生命周期；选择器、导入结果和进度内容保留异步完成/取消语义。此要求取代首轮允许独立工具窗的决定。

## 4. 各区域设计要求

### 4.1 主界面与插件库

- 页面标题明确标识插件库，目录路径作为次级信息；无目录、打开中、打开失败各有对应空态和可执行操作。
- 搜索、排序、视图切换与筛选集中在一致的工具区。筛选条件可辨认，支持清除；插件组路径保持可导航。
- 保留表格/瓦片等现有视图能力、多选、批量操作与原生虚拟化，合理保留数据密度。
- 详情区按基础信息、工坊信息、标签、依赖、高级设置分组；显示标题、说明与状态，避免粗边框层层套叠。
- 窄窗时详情面板折叠或切入详情页，主列表与关键命令仍可使用；不以固定宽度让按钮或文本被裁切。
- 检查、推送、下载与问题状态使用一致的反馈区域，避免同一状态在多处重复争夺注意力。

### 4.2 设置

按现有设置项划分分类，例如外观与语言、游戏、工坊与下载、冲突检查、备份、网络与高级。分类须覆盖全部现有设置，不因重新分组删除不常用项。

设置页面采用 Windows 11 设置式卡片：左侧可选图标，中部标题与说明，右侧控件或进入箭头；相关子项用 Expander 渐进展开。布尔设置优先 ToggleSwitch；多选集合保留 CheckBox；枚举使用 ComboBox；路径输入配合选择/打开命令；数值输入保留范围校验与失败反馈。

即时保存、需重启、加载中、无效值和依赖其他开关的状态必须清楚。保持现有保存语义；如需改变保存时机，应单独记录并验证，不能由布局改动隐式引入。

优先评估当前兼容版本的 Community Toolkit SettingsCard / SettingsExpander 等公开能力；确认 API、目标框架与许可后决定依赖。已有库提供时直接使用，不预先自行重写同类控件；确有能力缺口再记录理由实现。

### 4.3 工具窗与通用对话框

统一窗口标题、页面标题、内容留白、主次命令位置和操作状态。表单类使用设置行与分组卡片；数据密集类保留虚拟化列表、主从视图和批量操作，不把数据行强行设置卡片化。

覆盖设置、标签、问题/冲突、下载、名称自动设置、文件名修复、新建合集、导入结果、自定义图片、节点选择、文件清理器、替换总览、工坊 VPK 查找器及进度/关于/异常提示等视图。实施时建立逐窗清单，记录改动范围与未完成项。

ContentDialog 统一标题、正文与主次按钮；长异常仍可滚动和选择文本；选择器、模态归属、取消、关闭与再次打开保持正确。AddAddonTag 自动补全等旧功能遗留仍归 P7，若 P6 改到相同区域，可提前修复并记录证据。

## 5. 公共视觉与交互规范

| 项 | 设计要求 |
|---|---|
| 字体层级 | 使用 WinUI 系统字体与标题/正文/说明层级，页面标题、分组标题和设置标题清晰区分 |
| 间距 | 以 4 DIP 为基本步长，优先 8/12/16/24/32；页面留白、卡片内边距、行距集中定义 |
| 容器 | 使用系统主题背景、卡片填充和细描边，避免固定灰色粗框；圆角统一使用主题资源或集中定义 |
| 颜色 | 使用 ThemeResource 及语义状态色；适配浅色、深色和高对比度，不能仅靠颜色表达状态 |
| 图标 | 优先系统 SymbolIcon / FontIcon；保留必要领域图标；遵守 P3 的 Geometry 共享与绑定限制 |
| 材质 | Windows 11 可使用受支持的 Mica；不可用、禁用透明或系统降级时使用可读的实体背景 |
| 标题栏 | 保持系统窗口控制与拖动、最大化行为；自定义标题栏须验证按钮命中区与高 DPI |
| 命令 | 主操作突出、次操作克制、危险操作明确；保留禁用态与执行中反馈 |
| 无障碍 | 键盘可到达、焦点可见、合理 Tab 顺序、图标按钮具有辅助名称，尊重系统设置 |
| 本地化 | 新增文案同步中英文资源，避免硬编码；保留现有语言切换约定 |

具体尺寸在首批主窗与设置样板中校准，并集中到公共资源。上述间距为设计起点，不是未经测试的窗口最低尺寸承诺。

## 7. P6 验收标准

- [ ] 主窗以清楚的侧边导航和页面层级组织任务，高频操作可直接发现；不再以原菜单布局作为整套界面的骨架。
- [ ] 设置按分类与卡片组织，具备标题、说明、控件和依赖反馈，全部原设置项有去向。
- [ ] 主界面、详情、工具窗、对话框使用一致的字体、间距、主题颜色、命令与状态规范。
- [ ] 每个既有命令与工具入口都在映射清单中，旧快捷键、右键、多选和插件组导航仍可使用。
- [ ] 页面切换、关闭重开、加载/取消/异常、命令禁用态和 VM 生命周期通过改动范围内的回归。
- [ ] 在 Windows 11 浅色/深色、100%/150%/200% 缩放、宽窗/窄窗及高对比度下检查关键页面，无关键内容裁切或不可读状态；记录实际窗口尺寸与环境。
- [ ] 对目标兼容系统验证材质/标题栏降级；无法实测的环境标明未验证。
- [ ] 列表保留虚拟化；在可控大目录上比较改版前后滚动、选择和图片加载，记录数据规模与环境，处理明显退化。
- [ ] Debug 构建与既有测试通过；生成 exe 可运行；不能用构建或菜单可见替代界面操作验证。
- [ ] 留存主窗、设置、浏览/详情、代表性表单与数据工具窗的改版前后截图和关键操作记录，供用户验收。
- [ ] 完成七段式 `phase-notes/P6-native-ui.md` 并与阶段代码同提交，更新总计划与阶段索引；未验证项按规则标 🟡 并逐项归属。

本次文档调整不代表上述项目已通过，也不产生 P6 完成结论。

## 8. 与 P7 的交接与风险

P6 必须验证所有被改动的页面与交互；P7 负责最终全窗口、全业务链路验收。P3～P5 原计划中的工具窗交互、标签建议、权限推送、性能复验、偶发测试问题，以及打包、CI、README/CHANGELOG 等收尾工作归 P7 统一销项。P6 提前处理的遗留须有证据，P7 仍做整体验收。

| 风险 | 应对 |
|---|---|
| 导航重组导致命令不可达、选择或返回状态丢失 | 先列入口映射，逐项检查可达性与上下文 |
| 卡片与嵌套滚动增加布局成本，数据密度下降 | 数据区域保持列表虚拟化，性能比较包含图片与大目录 |
| 页面化改变窗口服务、模态归属或 VM 生命周期 | 最小范围调整，验证打开/关闭/切换/取消，遵守既有服务抽象 |
| 视觉判断只有源码、缺少实际界面证据 | 必须截图与操作点验；环境不可用时标未验证，不作通过结论 |
| 新控件库与现有 WinUI/.NET 版本不兼容 | 先验证公开 API 与依赖；不为视觉改版随意升级基础框架 |

阶段完成时，把入口映射、设计资源、实测环境、已知差异、证据位置及明确的 P7 遗留写入结论文档。未经证据验证，不更改 P4/P5 的有条件完成状态。
